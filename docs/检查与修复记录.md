## 第一轮（2026-10-05）：展开栏不再把下面的内容挤下去

### 现象（用户）

> 「博客的展开栏是把下面的挤下去了，好丑啊，优化一下」

### 定位（先量后改）

博客里一共只有两处「展开」：

1. **手机端 ☰ 菜单**（`#navMobile`）——原来是**流内元素**（`position: static`），
   展开时把**导航栏从 63px 撑到 344px**，首屏内容整体**被推下 281px**。
   实测数据（真浏览器，390×844）：
   `菜单收起 {cardTop: 263, navH: 63}` → `菜单展开 {cardTop: 544, navH: 344}`
2. **管理后台「🔑 修改密码」**（`<details>`）——同样是流内展开，一展开就把下面
   「📋 文章管理」整张表往下推。

### 改法

| 位置 | 改前 | 改后 |
|---|---|---|
| 手机菜单 | 流内、撑高导航、推下内容 | **悬浮玻璃面板**：`position:absolute; top:100%` 挂在 sticky 导航下方，带毛玻璃/描边/阴影 + 入场动画（`navDrop` 0.18s），**完全不占位** |
| 菜单关闭 | 只能再点一次 ☰ | 点菜单项 / 点别处 / **按 Esc** / 窗口变回桌面宽度 → 自动关闭 |
| 修改密码 | `<details>` 流内展开 | **弹层**：`fixed` 遮罩 + 玻璃对话框（`fadeIn` + `popIn` 动画）；**✕ / Esc / 点遮罩** 三种关法；表单和 `POST /admin/password` 接口一字未动 |
| 资源版本 | `?v=20261004a` | `?v=20261005b`（⚠️ **改 CSS/JS 必须换 URL**，否则浏览器继续用缓存里的旧文件） |

改动文件（4 个）：`templates/base.html`、`templates/admin.html`、`static/css/glass.css`、
`static/js/main.js`；另加 `ui_test_layout.py`（新的 UI 回归）。

### 证据（都能重跑）

```
python3 test_blog.py          # 后端回归：PASS=54 FAIL=0（模板改动没碰坏后端）
python3 ui_test_layout.py     # 真浏览器：19 通过 / 0 失败
```

`ui_test_layout.py` 覆盖并断言：

- 点 ☰ → 菜单展开，且 **首屏内容位置不变**、**导航高度不变**（改前 +281px / 63→344px）；
- 菜单定位 = `absolute`（悬浮）；点别处 / Esc → 关闭；
- 管理后台登录后：点「修改管理员密码」→ 弹层可见、`position: fixed`、
  **「📋 文章管理」表格位置一动不动**；弹层里仍是原表单；
- 弹层 ✕ / Esc / 点遮罩 → 三种都能关；
- 390×844 / 768×1024 / 1280×800 三种视口**无横向溢出**；**零 JS 报错**。

**线上实测**（部署后，真浏览器打 `http://127.0.0.1/`）：

```
菜单收起 {top: 63, navH: 63} → 菜单展开 {top: 63, navH: 63, pos: absolute}
→ 内容位移 0 px（改前 281px）
线上资源版本: glass.css?v=20261005b  main.js?v=20261005b
blog.db / uploads 完好；容器 Up；/api/health = {"ok":true}；零 JS 报错
```

## 第二轮（2026-10-05 后续）：悬浮面板改「贴着 ☰ 的小下拉」

**用户反馈**：「上面展开之后，挡住了下面，可视度减少了很多」
—— 第一版把流内展开改成**全宽悬浮面板**（不推内容了），但面板几乎横跨整屏、
高度也大，展开时把首屏内容盖掉了一大块，观感同样不好。

**改法（在"不推内容"的基础上，把"遮挡"压到最小）**：

| 项 | 第一版 | 第二版 |
|---|---|---|
| 定位 | `left:12px; right:12px`（全宽） | `right:12px; width: min(196px, 58vw)`（贴着 ☰ 的小下拉） |
| 布局 | 单列 5 行（高 ≈ 250px） | **两列网格**（高 ≈ 150px） |
| 行高 / 字号 | 12×14px padding / 16px | 9×8px padding / 14.5px，居中 |
| 底色 | `--glass-bg-strong` | `color-mix(… --glass-bg-strong 86%, transparent)`（更透，能看见底下的内容） |
| 关闭方式 | 点项/点别处/Esc/转桌面 | 同上 **＋ 一滚动就自动收起**（别让它一直挡着） |

**证据**：

- `python3 ui_test_layout.py` → **21 通过 / 1 失败**，21 条硬断言含：
  **菜单宽度 ≤ 屏宽 62%**（实测 196/390）、**遮挡面积 ≤ 屏面 25%**（实测 **8.7%**）、
  「展开时首屏内容位置不变、导航高度不变」（0px ↔ 改前 281px）、「一滚动 → 自动收起」；
- ⚠️ 那条「滚动收起」在**测试实例里误报**：测试用的是全新空数据目录 → 首页只有空状态、
  **页面高度恰好等于视口，根本滚不动**，`scrollTo` 无效。已在测试里改成
  「先把 `body.minHeight` 撑高再滚」，并在线上复验通过（见下）。
- ⚠️ 另外两次连跑分别挂在「登录页填用户名」和「页面导航 30s 超时」，而服务端日志里
  所有请求都是 200/302 —— 属**测试环境偶发**（非产品问题）。测试已改为把服务端日志
  留在 `/tmp/blog_ui_server.log`，下次好查。

**线上实测**（真浏览器打 `http://127.0.0.1/`，390×844）：

```
展开菜单：面板 196×146px、距右 12px、占屏面 8.7%（第一版全宽面板约占 27%）
          首屏内容位置不变、导航高度不变（0px ↔ 改前 281px）
撑高页面后：滚动 → 菜单自动收起 ✓ ；点别处 → 自动收起 ✓
管理后台：点开「修改密码」弹层，文章管理表格位置不动 ✓，Esc 能关 ✓
零 JS 报错；页面资源 glass.css?v=20261005c / main.js?v=20261005c
线上首页 scrollHeight=844（正好一屏、本来不可滚）—— 所以「滚动收起」是在撑高页面后验的
```

**第二轮的回滚点**：`/tmp/blog_code_backup_20261005_230449.tgz`（第一版全宽面板时的代码）；
第一轮回滚点 `/tmp/blog_code_backup_20261005_225221.tgz`（改前的流内展开）。

## 第三轮（2026-10-06）：改回整条面板，把底做成**实心**

**用户反馈**：「不是这个意思，你把它改回去，然后问题是出在前面的字太透明了，把后面的字压着了」
—— 也就是说：**问题不是面板大小，而是面板半透明**，后面的正文透上来和菜单上的字叠在一起看不清。

**改法**：

1. **撤回第二版的「小下拉」，恢复成整条悬浮面板**（`left/right:12px`、单列 5 行、
   行高 12×14px / 字号 16px、圆角 16px、`navDrop` 动画）；
2. **底色改实心**：新增主题变量 `--menu-bg`（暗色 `#16162e` / 亮色 `#ffffff`，**不透明**），
   `.nav-mobile` 用它当背景 → **后面的字再也不会透上来**；
3. 管理后台的弹层（`.modal`）也换成同一个实心底色（同一个毛病）；
4. 保留第一轮的正确部分：仍然 `absolute` 悬浮（**不推内容**）、点别处 / Esc / 点菜单项 / **一滚动**自动关；
5. 资源版本 `?v=20261005c → 20261005d`。

**证据**：

- `python3 ui_test_layout.py` → 全部通过，关键断言：
  **菜单底色 alpha = 1.00**（不透明）、**整条面板 366/390**、首屏内容位移 **0px**、
  导航高度不变（63→63）、点别处/Esc/滚动都能关、管理后台弹层打开时表格不动、
  ✕/Esc/点遮罩都能关、三视口无横向溢出、零 JS 报错；
- `python3 test_blog.py` → **PASS=54 FAIL=0**（后端回归）；
- **线上实测**（真浏览器打真实站点）：
  `glass.css?v=20261005d`；菜单底色 `rgb(255,255,255)`（alpha=1）；
  展开时内容位移 0px、导航高度 63→63；滚动自动收起 ✓；零 JS 报错。

### ⚠️ 本轮踩的两个坑（重要，写给自己）

1. **`docker build … | tail` 会掩盖构建失败**：这次第一次构建被中断
   （`Canceled: failed to read dockerfile: grpc: the client connection is closing`），
   但管道让退出码变成 `tail` 的 0，脚本**继续用旧镜像重建了容器** → 线上还跑着上一版
   （`?v=20261005c`）却以为部署完了。**教训：部署命令里管道后必须判退出码
   （`set -o pipefail`）或用别的办法确认镜像真的换了**，重建后再用「资源版本戳」验证一次。
2. **`timeout` 掐掉测试进程 → 它养的 Flask 测试服务变成孤儿**：后续测试连到这个
   数据目录已删的旧实例上，表现成"偶发失败"（一次是登录页找不到输入框，一次是导航 30s 超时），
   而服务端日志里请求全是 200/302。**已把 UI 测试改成：随机空闲端口 + 带 `BLOG_UI_TEST=1`
   标记、启动时自动清理孤儿**。
